What it does

Three things a driver can't do alone at 300 km/h

Watches the whole field

Gaps, closing rates, tyre age and pit stops for all 22 cars, so it can call an undercut, a car closing from 3 seconds back, or where you'd come out if you boxed now.

Says only what matters

Calls are settled before they're said, ranked by urgency and spoken once by the browser's own voice. Only a safety car, red flag, tyre cliff or fuel crisis takes over the screen.

Measures itself

Every prediction is replayed against real races and scored next to the obvious guess. Where a model doesn't beat that guess yet, the app says so.

How it works

One pipeline for live and replay

F1 26UDP, up to 60 Hz, 17 packet types
→
Parserspacked binary structs; layout drift degrades to a warning
→
Field modelevery car, on game time; flashbacks undone
→
Rules + modelscalls, pit loss, rejoin, battles, weather, ML
→
Dashboardone JSON snapshot, 10 Hz over WebSocket

A small Node bridge on the PC takes the game's UDP stream and serves the dashboard to any browser on the network. iOS can't listen for raw UDP, and this way an iPad only needs Safari. The browser formats; it never decides. Every call is made server-side, so this demo runs the exact code a live session does. One radio call traced end to end →

The harness also caught two bugs before release. The game reports a 0 s gap while a car is in the pit lane, which put rejoin predictions 8 places out during pit stops. And the first battery projection was worse than doing nothing. Samples are still small (3 green-flag stops, 20 passes), and the full report says so.

For engineers

What's under the hood

Binary protocol parsingLittle-endian packed structs across two game versions, pinned by tests on real F1 26 packets.
Real-time architecture60 Hz in, fixed 10 Hz out to every client, staleness detection, reconnecting clients.
ML from scratchLogistic regression with leave-one-race-out evaluation and calibration; live tyre-degradation fit across the field.
Evaluation harnessReplays recorded races and scores each prediction against a baseline; it found two real bugs.
UX for a glanceColour only means something, the decision is the biggest thing on screen, and auto-switching screens never flicker.
Lean by designNo build step, no framework, two small dependencies; under a millisecond per packet.
